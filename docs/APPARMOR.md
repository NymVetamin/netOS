# Совместимость с AppArmor

netOS не отключает AppArmor глобально и не переводит пакетные профили в complain.
Дополнения netOS ограничены собственными файлами и сокетами; дополнения
администратора должны сохраняться при применении, откате и удалении.

## Перечень интеграций

| Служба / исполняемый файл | Профиль пакета | Ресурсы netOS и способ совместимости |
|---|---|---|
| ISC DHCP `/usr/sbin/dhcpd` | `usr.sbin.dhcpd` | `generated/dhcpd.conf`, временная проверка с префиксом имени конфига, собственные аренды. Блок `netOS DHCP` в local. |
| Kea `/usr/sbin/kea-dhcp4` | `usr.sbin.kea-dhcp4` | `generated/kea-dhcp4.json`, временная проверка, `/var/lib/kea/netos-leases4.csv*`, lock в `/run/kea`. Блок `netOS DHCP`. |
| Kea LFC `/usr/sbin/kea-lfc` | `usr.sbin.kea-lfc` | То же семейство файлов аренды, включая ротацию. Проверять отдельно от выдачи DHCP-адреса. |
| Unbound `/usr/sbin/unbound` | `usr.sbin.unbound` | Конфиг и списки в `/etc/unbound/netos*`, изменяемый DNSSEC-якорь в `/var/lib/unbound/netos/root.key`. Собственный каталог root:root 0700 позволяет root-процессу создавать временные файлы без `dac_override`. Состояние переносится из прежних путей. |
| Входящий IKEv2, charon + swanctl | `usr.sbin.charon-systemd`, `usr.sbin.swanctl` | Дерево `generated/strongswan`, `/run/netos-strongswan/charon.vici`. Отдельный блок `netOS IKEv2`. |
| Исходящий IKEv2, charon + swanctl | Те же два профиля | Конфиги в `generated/netos-ikev2-chN`, каталог CA и сертификат; `/run/netos-ikev2-chN/charon.vici`. Отдельный блок `netOS IKEv2 channels`, подготовка до сетевых изменений. |
| Диагностика `/usr/bin/tcpdump` | `usr.bin.tcpdump` | Штатный профиль; захват и чтение pcap проверяются отдельно от перечисления интерфейсов. |
| dnsmasq, Samba, hostapd, pppd, xl2tpd, ocserv, openconnect | В проверенных пакетах Debian 12/13 собственного профиля нет | При установке дополнительных или пользовательских профилей требуется отдельная проверка. Отсутствие файла в пакете не доказывает отсутствие ограничений на конкретной ОС. |
| netosd, Xray, DNSproxy | netOS не поставляет профиль | Проверять фактическое `/proc/PID/attr/current`; профиль может быть установлен администратором. |

`generated` обозначает `/var/lib/netos/generated` при стандартной установке.
В профилях Kea из Debian 12 нет local include: для известной структуры этих
профилей netOS размещает маркированный блок внутри самого профиля и удаляет
только этот блок при удалении netOS. Неактивные local-файлы администратора
при этом не подключаются. Профили Debian 13 используют штатный local include.
Наличие профиля на диске, его загрузка и режим процесса — разные проверки.
Пакетный charon может по умолчанию работать в complain; это не равно проверке enforce.

## Изменение службы

При изменении путей, имени временного файла, пользователя процесса, сокетов или
дочерних программ обновлять этот перечень и соответствующие правила. Для Kea
учитывать владельца каталога аренды и запуск LFC, для Unbound — запись DNSSEC-якоря,
для swanctl — перечисление каталога CA, а не только чтение файла сертификата.

Проверки конфигурации и загрузки необходимых правил выполнять до остановки
рабочих служб. Они не заменяют проверку реального запуска и откат: некоторые
операции выполняются только во время работы.

## Обязательная проверка исправлений

1. Зафиксировать версии ОС и пакетов, загруженные профили и режимы процессов.
2. Воспроизвести отказ и связать его с конкретной операцией и записью аудита.
3. Проверить успешный запуск и реальную операцию: DNS-ответ, DHCP-аренду,
   передачу данных через VPN или захват пакетов.
4. Проверить повторное применение, изменение параметров, отказ с восстановлением,
   отключение и повторное включение, перезагрузку.
5. Проверить совместную работу потребителей общего профиля — входящего сервера
   и исходящих каналов IKEv2.
6. При удалении убирать только собственные маркированные блоки. Обязательный
   local include должен оставаться читаемым, даже если файл стал пустым.
7. Не считать тест без загруженного профиля или в complain проверкой enforce.

`DENIED` не всегда означает отказ функции. Например, Unbound может получить
отказ `SO_SNDBUFFORCE`, затем успешно выполнить `SO_SNDBUF`. Сначала проверяется
результат операции; дополнительные capabilities не выдаются только ради
отсутствия записей в журнале.
