# netOS

Превращает любой ПК или виртуальную машину на Debian в полноценный роутер,
управляемый через веб-панель. Одна команда для установки, дальше вся настройка
в браузере. Изменения применяются сразу, без перезагрузок.

```bash
curl -fsSL https://raw.githubusercontent.com/NymVetamin/netOS/master/install.sh | sudo bash
```

Скрипт сам определит интерфейсы, поднимет рабочую конфигурацию и напечатает
адрес панели, логин и пароль.

## Управление установленной системой

После установки используется команда `netos`. `netosd` — внутренний демон
(`d` означает daemon), который запускает systemd; вручную вызывать его не нужно.

```bash
netos status                 # состояние
sudo netos logs -f           # журнал
sudo netos plan              # чем живая система расходится с конфигурацией
sudo netos update            # обновление до последнего релиза
sudo netos update v1.2.3     # обновление до конкретной версии
sudo netos reinstall         # развернуть текущую версию заново
sudo netos backup            # ручная резервная копия
sudo netos restore           # список копий и восстановление из выбранной
sudo netos reset             # заводской сброс
sudo netos uninstall         # полное удаление с резервной копией
sudo netos render sysctl     # какие параметры ядра ставит netOS
sudo netos render resolv     # к какому резолверу netOS отправляет сам роутер
netos help                   # все команды
```

Команды дополняются по Tab: установщик кладёт скрипт дополнения в
`/etc/bash_completion.d/netos`, и он начинает работать в следующей сессии
оболочки. Получить его отдельно: `netos completion bash`.

`update` разворачивает версию заново, сохраняя конфигурацию, пользователей и
TLS-сертификаты. Если запрошенная версия уже установлена, он это говорит и
ничего не делает: несколько минут загрузки и перезапуск службы ради нулевого
результата никому не нужны. Развернуть ту же версию заново — `netos reinstall`
или `netos update --force`; за этим приходят, когда установка развалилась.

`plan` ничего не меняет. Он сравнивает живую систему с активной конфигурацией
netOS и печатает, что изменилось бы при её применении, помечая восклицательным
знаком то, что кратковременно рвёт связность.

`backup` и `restore` работают с каталогом `/var/backups/netos`. Копия — это
`/var/lib/netos`, `/etc/netos` и `/var/log/netos` целиком: конфигурация,
история ревизий, учётные записи и сертификат панели. `restore` без аргументов
показывает список копий и спрашивает, какую взять; перед восстановлением он
всегда сохраняет текущее состояние отдельной копией `before-restore`.

Перед `reset` копия предлагается вопросом (`--backup` и `--no-backup` отвечают
на него заранее), перед полным `uninstall` создаётся всегда. Новые данные для
входа `reset` печатает прямо на экран.
Для автоматизации подтверждение передаётся флагом `--yes`; команда
`uninstall --keep-data` оставляет каталоги данных на месте.
Пакеты компонентов, установленные через apt, при удалении не вычищаются:
они могут использоваться другими задачами системы.

На машине со старой версией, где команды `netos` ещё нет, достаточно один раз
повторно запустить установщик. Он сохранит существующую базу и добавит CLI;
последующие обновления выполняются уже через `sudo netos update`.

## Что уже умеет

**Базовое**
- Интерфейсы, бриджи, VLAN, bond
- Несколько LAN-сегментов со своими подсетями и изоляцией
- WAN: DHCP, статика, PPPoE и L2TP; Multi-WAN failover и взвешенная балансировка с активными пробами
- DHCP-сервер на выбор: dnsmasq, isc-dhcp-server, kea
- DNS-резолвер на выбор: dnsmasq, unbound или dnsproxy — с DoT/DoH/DoQ
- Статические адреса по MAC и локальные DNS-записи
- Split-DNS с отдельным апстримом и привязкой DNS-соединений к VPN-каналу
- DNS blocklists из HTTPS-источников: plain/hosts/Adblock, общий кэш и атомарное
  применение для dnsmasq, unbound и dnsproxy с возвратом прежнего списка при ошибке
- Файрволл на iptables: зоны, правила, проброс портов, SNAT, защита от сканов и SYN-флуда
- Список клиентов, ARP-таблица и аренды; блокировка, выбор канала и индивидуальные лимиты скорости по MAC
- CAKE для WAN и HTB/policing для клиентских download/upload-лимитов
- История скорости за 24 часа с хранением семи суток
- DDNS: Cloudflare, DuckDNS и No-IP, адрес с интерфейса или внешнего сервиса

**VPN**
- Исходящие WireGuard-, OpenConnect- и Xray-каналы (VLESS, VMess, Trojan, Shadowsocks, Reality и другие транспорты Xray)
- Входящие WireGuard, VLESS Reality, OpenConnect и IKEv2: отдельные клиенты, ключи/пароли и клиентские конфигурации
- Выбор канала выхода для клиента, сегмента, IP-адреса, домена, протокола или порта
- Активные ICMP/TCP/HTTP-проверки каналов с порогами отказа и восстановления
- Режим отказа на выбор: kill-switch, запасной канал или прямой выход

**Эксплуатация**
- Wi-Fi AP через hostapd: WPA2/WPA3, несколько SSID, скрытие и изоляция клиентов
- Резервные копии, восстановление и обновление прямо из панели с явным подтверждением опасных операций
- Ревизии, аудит, диагностика с фактически сгенерированными конфигами и безопасный автоматический откат

Не реализованы и намеренно отклоняются валидатором: AdGuard Home и исходящие
L2TP/IKEv2-каналы.
L2TP уже поддерживается как WAN-подключение провайдера, а IKEv2 — как входящий VPN-сервер.
Пользовательская TLS-пара и порт панели меняются в разделе «Система» отдельным
перезапуском: новая ревизия подтверждается ready-marker, а при нестарте автоматически
возвращается предыдущая активная ревизия.
Режим ACME получает и автоматически обновляет сертификат для публичного DNS-имени
через HTTP-01 на TCP/80; готовность новой ревизии подтверждается только после успешного
выпуска сертификата и ответа живого HTTPS API.

**IPv6** подавляется полностью и намеренно — чтобы трафик не утекал мимо
VPN-канала. Режим переключается в настройках.

## Архитектура

Подробности в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Кратко:

- один бинарник `netosd` на Go со встроенным фронтендом;
- вся конфигурация — JSON-документ в SQLite, каждое применение создаёт ревизию;
- подсистемы рендерят конфиги демонов и применяют их атомарно;
- после применения запускается таймер: не подтвердил — автоматический откат
  к предыдущей ревизии (спасает, когда правило файрволла отрезало доступ);
- маршрутизация по клиентам: fwmark в mangle → `ip rule` → своя routing-таблица
  на каждый канал.

## Состояние разработки

| Фаза | Содержание | Статус |
|---|---|---|
| 1 | Ядро, инсталлер, базовый роутер: сеть, DHCP, DNS, NAT, файрволл, панель | готова |
| 2 | Каналы, политики маршрутизации, WireGuard-клиент, Multi-WAN | готово |
| 3 | Xray, OpenConnect, PPPoE и L2TP на WAN | готово |
| 4 | WireGuard, Reality, OpenConnect и IKEv2-серверы; Wi-Fi | готово |
| 5 | Статистика, QoS, DDNS, бэкапы, обновление и адаптивная панель | готово |

Работает и проверено на живой машине:

- установка одной командой: базовая установка ставит **только панель и SSH**,
  всё остальное выбирается в разделе «Компоненты»;
- автоопределение интерфейсов; на машине с одной сетевой картой локальный
  сегмент не создаётся вовсе;
- декларативное применение с ревизиями, планом изменений и автоматическим
  откатом, если администратор не подтвердил, что связь жива;
- защита от самоблокировки: конфигурация, не оставляющая ни одного способа
  подключиться к роутеру, отклоняется проверкой и не применяется;
- файрволл на iptables: три цепочки по зонам, единый список правил без
  скрытых — то, что видно в панели, и есть то, что в ядре;
- маршрутизация: статические маршруты, дополнительные таблицы, правила выбора
  таблиц;
- исходящие WireGuard-каналы без `wg-quick`: отдельные таблицы, `fwmark` и
  `CONNMARK`, активный мониторинг, kill-switch/fallback/direct, NAT и выбор
  канала по политике, сегменту или конкретному клиенту;
- исходящие OpenConnect-каналы для AnyConnect/Pulse/GlobalProtect/Fortinet/F5
  и Xray-каналы через собственный TUN: импорт стандартных ссылок, произвольный
  outbound JSON, отдельная таблица, kill-switch и проверка реального трафика;
- установка и удаление компонентов из панели: каталог из 16 позиций;
- DHCP и DNS через dnsmasq, статические привязки, локальные записи;
- шифрованный DNS: unbound (DoT, DNSSEC) и dnsproxy (DoT, DoH, DoQ, фильтр
  AAAA); локальные имена при этом остаются за dnsmasq, а панель показывает
  получившуюся цепочку резолва схемой;
- подавление IPv6 на всех уровнях: sysctl, ip6tables, фильтрация AAAA;
- клиент DHCP для аплинка на udhcpc, не трогающий общесистемные файлы;
- PPPoE и L2TP на аплинке: логин и пароль провайдера, предсказуемое имя
  интерфейса сессии, бесконечный автодозвон после обрыва; у L2TP адрес в сети
  провайдера берётся по DHCP или задаётся вручную;
- персистентная конфигурация сети для ifupdown и systemd-networkd: бриджи,
  VLAN и адреса сегментов существуют уже с загрузки, до старта netosd;
- веб-панель: сводка, клиенты, интерфейсы и сегменты, маршрутизация, файрволл,
  каналы, VPN-серверы, Wi-Fi, QoS/DDNS, DHCP и DNS, компоненты, обслуживание,
  история ревизий и диагностика; desktop и мобильная раскладки используют один API.
- реальные Linux-интеграции для PPPoE, L2TP, WireGuard, IKEv2/XFRM,
  ocserv/OpenConnect, hostapd, Multi-WAN, CAKE/HTB, ifupdown/networkd и DHCP-провайдеров.

## Разработка

Перед первой правкой — [CLAUDE.md](CLAUDE.md): принятые решения, которые
выглядят как ошибки, требования к подсистемам и к проверке изменений. Файл
общий для людей и для агентов.

```bash
# развернуть на тестовую машину, собрать и перезапустить
NETOS_HOST=netos ./scripts/dev-deploy.sh --restart --vet

# фронтенд
cd web && npm install && npm run build

# интеграционные тесты (на тестовой машине, под root): поднимают настоящий
# концентратор PPPoE, systemd-networkd и временный WireGuard-интерфейс
NETOS_INTEGRATION=1 go test ./internal/subsys/... -run "PPPoE|Integration" -v
```

Сборка фронтенда кладёт файлы прямо в `backend/internal/api/webdist`, откуда
они встраиваются в бинарник.

## Требования

- Debian 12 или 13, архитектура amd64 или arm64
- root-доступ, systemd
- не менее 512 МБ ОЗУ для работы; для сборки из исходников нужно около 2 ГБ ОЗУ и подкачки суммарно
- минимум два сетевых интерфейса для работы роутером (или один — для режима
  «роутер на палочке» с VLAN)
