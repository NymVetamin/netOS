# netOS

Превращает любой ПК или виртуальную машину на Debian в полноценный роутер,
управляемый через веб-панель. Одна команда для установки, дальше вся настройка
в браузере. Изменения применяются сразу, без перезагрузок.

```bash
curl -fsSL https://raw.githubusercontent.com/<owner>/netos/main/install.sh | sudo bash
```

Скрипт сам определит интерфейсы, поднимет рабочую конфигурацию и напечатает
адрес панели, логин и пароль.

## Что умеет

**Базовое**
- Интерфейсы, бриджи, VLAN, bond
- Несколько LAN-сегментов со своими подсетями и изоляцией
- WAN: DHCP, статика, PPPoE; Multi-WAN с failover и балансировкой
- DHCP-сервер на выбор: dnsmasq, isc-dhcp-server, kea
- DNS-резолвер на выбор: dnsmasq, unbound, dnsproxy, AdGuard Home — с DoT/DoH/DoQ
- Статические адреса по MAC, локальные DNS-записи, split-DNS
- Файрволл на iptables: зоны, правила, проброс портов, SNAT, защита от сканов и SYN-флуда
- Список клиентов, ARP-таблица, аренды, статистика трафика
- Wi-Fi точка доступа через hostapd

**VPN**
- Исходящие каналы: WireGuard, Xray (VLESS/VMess/Trojan/Shadowsocks, Reality, XTLS, WS, gRPC), OpenConnect, L2TP/IPsec, IKEv2
- Входящие серверы: WireGuard, IKEv2, ocserv, Xray inbound
- Выбор канала выхода для каждого клиента, сегмента, домена или порта
- То же самое для клиентов, подключённых к роутеру по VPN
- Kill-switch на канал: при падении туннеля трафик не уходит напрямую

**IPv6** подавляется полностью и намеренно — чтобы трафик не утекал мимо
VPN-канала. Режим переключается в настройках.

## Архитектура

Подробности в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Кратко:

- один бинарник `netosd` на Go со встроенным фронтендом;
- вся конфигурация — JSON-документ в SQLite, каждое применение создаёт ревизию;
- подсистемы рендерят конфиги демонов и применяют их атомарно;
- после применения запускается таймер: не подтвердил — автоматический откат
  к предыдущей ревизии (спасает, когда правило файрволла отрезало доступ);
- маршрутизация по клиентам: fwmark в mangle → `ip rule` → своя routing-таблица
  на каждый канал.

## Состояние разработки

| Фаза | Содержание | Статус |
|---|---|---|
| 1 | Ядро, инсталлер, базовый роутер: сеть, DHCP, DNS, NAT, файрволл, панель | почти готова |
| 2 | Каналы, политики маршрутизации, WireGuard-клиент, Multi-WAN | — |
| 3 | Xray, OpenConnect, L2TP/IPsec, IKEv2 | — |
| 4 | VPN-серверы, Wi-Fi | — |
| 5 | Статистика, QoS, DDNS, бэкапы, обновление из панели | — |

Работает и проверено на живой машине:

- установка одной командой: базовая установка ставит **только панель и SSH**,
  всё остальное выбирается в разделе «Компоненты»;
- автоопределение интерфейсов; на машине с одной сетевой картой локальный
  сегмент не создаётся вовсе;
- декларативное применение с ревизиями, планом изменений и автоматическим
  откатом, если администратор не подтвердил, что связь жива;
- защита от самоблокировки: конфигурация, не оставляющая ни одного способа
  подключиться к роутеру, отклоняется проверкой и не применяется;
- файрволл на iptables: три цепочки по зонам, единый список правил без
  скрытых — то, что видно в панели, и есть то, что в ядре;
- маршрутизация: статические маршруты, дополнительные таблицы, правила выбора
  таблиц;
- установка и удаление компонентов из панели: каталог из 16 позиций;
- DHCP и DNS через dnsmasq, статические привязки, локальные записи;
- подавление IPv6 на всех уровнях: sysctl, ip6tables, фильтрация AAAA;
- клиент DHCP для аплинка на udhcpc, не трогающий общесистемные файлы;
- веб-панель: сводка, клиенты, интерфейсы и сегменты, маршрутизация, файрволл,
  DHCP и DNS, компоненты, система, история ревизий, диагностика.

Осталось в первой фазе: провайдеры unbound и dnsproxy для DoT и DoH,
поддержка PPPoE и L2TP на аплинке, генерация конфигураций для ifupdown и
systemd-networkd, сборка релизов в CI.

## Разработка

```bash
# развернуть на тестовую машину, собрать и перезапустить
NETOS_HOST=netos ./scripts/dev-deploy.sh --restart --vet

# фронтенд
cd web && npm install && npm run build
```

Сборка фронтенда кладёт файлы прямо в `backend/internal/api/webdist`, откуда
они встраиваются в бинарник.

## Требования

- Debian 12 или 13, архитектура amd64 или arm64
- root-доступ, systemd
- минимум два сетевых интерфейса для работы роутером (или один — для режима
  «роутер на палочке» с VLAN)
